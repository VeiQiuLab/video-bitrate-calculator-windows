视频码率计算器 v1.0（Windows / Python / Tkinter）
==========================================

一、这是做什么的？
-----------------
根据“原片时长 + 上传网站文件大小上限”，计算 H.264 / H.265 / AV1 / VP9
四种编码格式可使用的视频平均码率，并生成完整的 HandBrake 推荐设置。

默认：网站 180 MB 上限，实际目标 170 MB，AAC 128 Kbps 音频，1.5% 封装余量。
应用程序不上传视频，不联网，不修改原始文件，也不负责实际转码。

二、使用方法
-----------
1. 打开 视频码率计算器（Python 用户可双击 bitrate_gui.pyw；打包后双击 .exe）。
2. 点击“选择原片，自动读取时长”，或手动输入 9:38、1:09:38 等格式。
3. 调整上传上限、安全目标、音频总码率、封装余量及画面类型。
4. 点击 AV1 / H.265 / H.264 / VP9 任何一行，查看对应完整编码建议。
5. 点击“复制码率”“复制所选格式完整参数”“复制全部四种编码参数”
   或“导出 TXT”。
6. HandBrake 设置为 Average Bitrate，输入显示的 Kbps，按建议使用
   编码器与多遍编码；完成后检查最终大小和实际画质。

三、为什么四种编码的 Kbps 数字相同？
----------------------------------
码率由总时长、体积目标、音频以及封装共同决定，与视频编码器无关。
AV1、H.265、H.264、VP9 的区别是“同一个码率下的画质/编码时间/兼容性”。
例如文件容量只有 170 MB，不能指望 H.264 编码自动分到比 AV1 更多的空间。
为了质量，优先试 AV1 (SVT-AV1)，然后 H.265，再根据兼容性考虑 H.264。

四、数学公式
------------
以十进制单位为准，1 MB = 1,000,000 Bytes：
  视频 Kbps = 向下取整[ (目标 MB × 8000 / 时长秒) × (1 - 封装余量%) - 音频 Kbps ]
举例：目标 170 MB，时长 9:38 (578 秒)，音频 128 Kbps，余量 1.5%
计算结果约 2189 Kbps。表格各编码结果均基于同一个预算。
注意：这里的百分比是人为预留的余量，不是某种封装格式精确固定占比。

五、自动识别时长
----------------
有两种方式：
  1. 自带轻量解析：支持有有效时长元数据的 MP4/MOV/M4V 和 MKV/WebM。
  2. 优先使用 ffprobe.exe：放在打包后的 EXE 同目录或系统 PATH，
     就可读取更多常见格式及特殊文件；
     归档版构建脚本不捆绑 ffprobe.exe；请独立放置并核对其版本及协议。
ffprobe 是 FFmpeg 套件中的工具；下载时请从 FFmpeg 官方渠道或可信镜像获取，
遵守其具体许可协议及再分发条件。
读取失败时手动填写时长即可，计算功能不受影响。

六、让没有 Python 的人直接运行（Windows EXE）
---------------------------------------------
【只有制作 EXE 的电脑需要安装 Python，使用者不需要】
Windows 电脑执行：
  1. 从 https://www.python.org/downloads/windows/ 安装 Python 3.10 或更新版；
  2. 确保本目录中有 bitrate_core.py、bitrate_gui.pyw、test_bitrate_core.py；
  3. 双击 build_windows.bat；它会先测试，再安装 PyInstaller 并打包；
  4. 生成 dist\VideoBitrateCalculator.exe。
把这个 EXE 发给对方，对方不需要 Python、pip、HandBrake 或其他运行组件。
* HandBrake 只有在对方需要“转码”时才须额外安装；计算器本身不进行转码。
* 未附带 ffprobe 的情况下，部分特殊媒体格式不能自动识别时长；可手动输入。
* 未签名的个人 EXE 可能被 Windows SmartScreen 询问确认，请勿盲目关闭安全防护。

七、原片怎么录？
----------------
如果是 1080p60 高质量原片：
  优先 OBS 的高质量/恒定质量模式；若必须指定平均码率，
  可从 HEVC 30–40 Mbps 试起，游戏高速运动时可适当提高。
  上传用版本和原片分开保存，不要多次有损转码。
网站版：HandBrake 选 Average Bitrate 和多遍编码，优先 AV1。

八、限制与免责
--------------
- 网站可能按 MiB 而不是 MB 计大小；本工具采用十进制 MB，另留体积余量。
- 双遍平均码率尽量贴近目标，但仍可能有偏差；最终体积不是硬保证。
- 相同体积下，越长的视频，每秒视频码率越低，画质可能下降。
- “推荐分辨率 / FPS”仅经验估计，不代表任何游戏、设备或网页播放都无损。
- 某些编码器/多遍选项在不同 HandBrake 版本或硬件编码器上显示不同。
- 原片如果本身已经糊了，转码无法恢复丢失的细节。
